/chat

Chat & inline execution cards

Replaces the earlier conversation specimen; #conversations remains an alias.

Conversation rail, restrained transcript, persistent composer, prompt suggestions, compact action card, separate shared review.

  • Prompt suggestions fill the composer; sending an action creates a typed local specimen.
  • Missing amount/asset and ambiguous Sentora products request clarification. Unsupported venue actions never silently change venue.
  • Only validated application events may create native action cards in production. Model prose stays escaped/inert.
  • Preparation, review, blocked, expired, wallet mismatch, signature, submission, reconciliation, partial completion and confirmed states remain distinct.
  • Stop response does not cancel a prepared plan. Dismiss plan is a separate control.
  • No automatic spending threshold, delegated signer or mandatory extra caps.
  • Deposit cards and the shared review keep venue-specific withdrawal conditions visible.

Planned bindings: GET /api/agent/conversations; POST /api/agent/conversations/:id/messages; GET /api/agent/runs/:id/events; POST /api/agent/runs/:id/abort; POST /api/intents; POST /api/intents/:id/compare; POST /api/plans; prepare/approve/submit; persisted plan events

Market detail & read inspector

New dynamic market route.

Market header, policy context, amount presets, comparable route bars or lending/vault terms, underlying composition, assets/identity and read inspector.

  • Spot offers 100/1,000/10,000 XLM fixture comparisons; route output changes with the selected amount.
  • Review in chat carries the exact requested amount via in-memory draft, never a URL amount parameter.
  • Lending/vault variants preserve native risk, capacity, fees, settlement and missing data.
  • Read inspector distinguishes requested/succeeded/empty/partial/stale/error with provenance in production; preview shows Not requested.
  • No synthetic orderbook, fake ledger ID, fabricated receipt link or unconditional live-status badge.

Planned bindings: GET /api/markets; POST /api/intents/:id/compare; Native protocol/API/RPC read results and per-read provenance; Shared action review and application plan lifecycle
