# React workspace behavior

The application runs with `pnpm dev`. `design/nest/ui` is the visual reference; its labeled financial fixtures are never live application data.

| Area | React behavior |
| --- | --- |
| Workspace | Forest surfaces, cream typography, orange actions, underlined primary navigation and a floating Ask Nest control. Guardrails stays beside the wallet. The assistant retains the current conversation, reader-controlled scrolling and desktop resize behavior. |
| Credit | A centered two-panel builder keeps all five terms visible beside the active editor. Apply retains the local draft. Compare carries every requested constraint into an unsent assistant draft. Reference Blend rates are live reads; they are not a complete quote for the form. Unsupported collateral, horizon or APR constraints must not be silently dropped by a proposal. |
| Supply | A centered intent panel and comparison panel share their width. Exact supported amounts create an application-owned lending intent and use the existing pool comparison, trustline, policy, review and signing components. The horizon is research context, not a fixed loan term. |
| Research | DeFi, RWAs and MCP Contents share source stamps, filtering, exports, density and pagination. The chain summary and dated history precede the compact, ranked DeFi protocol directory; CEX rows and rows without Stellar TVL are excluded. RWA composition and league tables use captured provider shares. The venue map groups projects by their captured Scout identity and preserves dated descriptions and evidence counts. MCP Contents includes the venue map. Detail routes preserve source and asset identities. |
| Earn | Lending, vaults, campaigns and liquidity retain the shared filter rail and horizontal opportunity rows. Live DeFindex vaults appear inside the shared opportunity list, filters and pagination, with the existing deposit flow available from each executable row and its detail page; public Aquarius observations retain network and retrieval time. Exit timing and provider-sourced strategy facts remain visible. |
| Trade | The three-part workspace contains candlestick context, route facts and an exact-input ticket. Captured Mainnet reference candles are labeled with their source and date, independently of the wallet network. The chart supports interval aggregation, zoom, pan and fit. Quotes, policy, fees, trustlines, signatures and confirmations use the existing execution service. |
| Chat | The conversation rail starts compact and expands on hover, keyboard focus or explicit pinning. Example prompts and the amount/asset/horizon form populate an unsent draft. Model streaming, stop controls and financial proposal cards retain the shared runtime and application records. |
| Lab | Backtest and Set automation start with a guided thesis conversation. The existing arbitrage builder, saved rules and evaluation evidence remain connected. A labeled, local-only arbitrage simulation demonstrates gap crossing, duplicate-alert suppression, re-arming and reset without touching saved monitors. Historical replay remains unavailable; the UI produces no invented backtest performance. |
| Portfolio | A composition panel places the total under its heading, followed by a full-width positions/exit area. Unknown balances, valuations and cost basis remain unavailable. Funding, spend preview, activity and native management routes remain accessible. |

Financial state persists in application records independently of chat history. The agent never signs. Every financial action still requires the existing exact-plan review and wallet signature. Committed execution switches remain off.

Protocol research details use validated captured descriptions, scope, yields, project references and source links in the shared reference layout. RWA asset links open RWA.xyz directly. Trade's searchable asset window is shared by the market, pay and receive controls. See [the UI coverage audit](ui-parity-audit.md) for inspected surfaces and remaining account-state differences.

Unsaved inputs and display preferences are local drafts. Guardrail settings require explicit user action. Missing source data is never replaced with sample prices, balances, health factors or successful receipts.
